## 1. Product definition

This is an advanced follow-on to Moonlighter’s Basic 3D Printing class. Participants begin with a reference image and a written transformation prompt, use a replaceable AI image tool to develop a print-friendly concept, convert the selected image into a three-dimensional mesh, inspect and optionally repair the geometry, slice it in Bambu Studio, and prepare an approved small-format print.

The workshop teaches a transferable method rather than a single vendor interface:

**Reference + prompt → generated image → image-to-3D mesh → validation → optional repair → scale/orientation/supports → slicing → instructor approval → print or queue → project archive**

The website is a teaching instrument, not simply a promotional page. One canonical curriculum powers:

- Participant mode on Moonlighter computers.
- Synchronized presentation mode on the room display.
- Facilitator controls, timing, checkpoints, and printer assignments.
- Post-class reference pages and downloadable documentation.
- A participant project archive and Moonlighter production handoff.

### Workshop promise

By 4:00 PM, every participant should leave with:

- A clear concept derived from their own reference and prompt.
- A selected AI-generated source image.
- An original exported 3D conversion.
- A validated or repaired printable mesh.
- A scaled and sliced Bambu Studio project.
- A complete set of source and production files.
- One approved print attempt, launched during class when possible or entered into the post-workshop queue.

This workshop does not certify independent printer operation. Printer submission, approval, and operation remain instructor/Moonlighter controlled.

## 3. Participant project envelope

Creative choice remains open, but the site explains the physical consequences of each choice.

### Baseline constraints

- One primary, solid object.
- A clear silhouette and recognizable main mass.
- A flat base or an orientation that can be stabilized with supports.
- Single-color PLA for the pilot.
- Avoid paper-thin limbs, floating parts, deep inaccessible cavities, tiny isolated text, and details smaller than the provisional nozzle can resolve.
- Every size remains conditional on the actual Bambu Studio time and material estimate.

### Two production tiers

| Tier | Provisional size | Typical estimate | Class outcome | Site label |
| --- | ---: | ---: | --- | --- |
| Miniature | 35–70 mm | Usually under 90 minutes | Prioritized for an in-class launch; may finish during class; second personal iteration only if spare capacity exists | **MINI / QUICK** |
| Sculpture | 80–120 mm | Often 90–240+ minutes | Instructor approval required; normally queued for collection | **SCULPTURE / QUEUED** |

These ranges are guidance, not a guarantee. Geometry, orientation, layer height, support volume, infill, nozzle, material profile, and the exact printer model govern the final estimate.

### Time classes shown after slicing

- **Quick Print:** under 60 minutes.
- **Standard Print:** 60–120 minutes.
- **Extended Print:** over 120 minutes; resize, reorient, or queue.

### Support rating

Every project receives a visible rating paired with an icon and plain-language label:

- **Low support:** limited contact points; short removal time.
- **Moderate support:** meaningful added time/material; some surface marking expected.
- **High support:** complex removal, fragile contact points, or significant print-time increase; instructor review required.

## 5. Curriculum module specifications

Each module follows one repeated layout:

1. One large editorial process image.

3. A compact technical strip: **Input / Tool choices / Timebox / Output / Pass check**.
4. A short original demo.
5. A guided task card.
6. A pass/fix checkpoint.
7. Collapsed tips, external reference, and troubleshooting.

### Module 0 — Enter the Lab

**Header:** FROM IMAGE TO OBJECT  
**Subhead:** One reference. One prompt. One printable decision.  
**Objective:** Understand the complete workflow and prepare a project folder before opening any AI tool.

**Input:** Session code, participant name, reference options  
**Tools:** Workshop site, local file system  
**Timebox:** 20 minutes  
**Output:** Named project folder and selected PLA preference  
**Pass check:** Participant can identify the next three stages and has saved to the correct folder

**Demo example:** A single generated object shown as image, mesh, slicer preview, and physical print.

**Guided task:**

- Join the session.
- Choose **Follow class** or **My pace**.
- Create the required folder structure.
- Select first and second PLA choices.
- Review Miniature vs Sculpture tier.

**Original video:** 45–60 seconds, “The entire image-to-object pipeline.”  
**External support:** Bambu Studio overview or Moonlighter’s Basic 3D Printing refresher.  
**Documentation:** One-page workflow map and file checklist.

### Module 1 — Choose the Signal

**Header:** CHOOSE A REFERENCE THE MODEL CAN READ  
**Subhead:** Clear silhouette first. Style and detail second.  
**Objective:** Select or make a reference with enough visual separation to support image transformation and 3D inference.

**Input:** Uploaded file, brought file, or new photograph  
**Tools:** Camera/file browser  
**Timebox:** 30 minutes  
**Output:** `01_reference/original.ext` plus a cropped working copy  
**Pass check:** One main subject, complete silhouette, readable lighting, simple background

**Different example for this module:** Strong and weak photographs of the same small object.

**Teach:**

- One dominant subject.
- Three-quarter or near-frontal view when useful.
- Full silhouette inside frame.
- Avoid occlusion, cropped limbs, heavy shadows, reflective glare, clutter, and transparent objects.
- Participants must have permission to use the image; do not upload private or sensitive images casually.

**Reference-quality meter:**

- **Green / Ready:** clear subject, separated background, complete silhouette.
- **Amber / Adjust:** usable after crop, background cleanup, or angle change.
- **Coral / Replace:** multiple subjects, hidden structure, severe glare, incomplete form.

**Original video:** 60–75 seconds, “Photographing an object for AI-to-3D.”  
**External reference:** Official Meshy or Tripo guidance on image selection.  
**Documentation:** Reference-image checklist and consent/privacy note.

### Module 2 — Direct the Image

**Header:** DESIGN FOR VOLUME, NOT JUST APPEARANCE  
**Subhead:** The best-looking image is not always the best image to print.  
**Objective:** Combine a reference with a written transformation prompt that produces a clear, object-centered image.

**Input:** Working reference + prompt  
**Tool choices:** ChatGPT Images or Adobe Firefly; tool is replaceable  
**Timebox:** 45 minutes  
**Output:** 2–4 concepts and one selected final image  
**Pass check:** Chosen concept has one object, clear silhouette, coherent volume, visible base, and minimal background

**Different example for this module:** One household object transformed into a friendly miniature and an architectural sculpture.

**Transferable prompt formula:**

> Transform **[reference subject]** into **[new object/character direction]**. Preserve **[essential identity or shape]**. Show one complete object in a centered three-quarter view with a clear silhouette, coherent solid volumes, thick printable details, no floating parts, and a simple neutral background. The object should stand on **[integrated base / stable lower mass]**. Single-object product study, soft even lighting, no text, no props, no cropped edges.

**Prompt controls shown as selectable chips:**

- Subject identity
- Transformation
- Material/shape language
- Pose/view
- Base/stability
- Background
- Exclusions

**Negative guidance:** no multiple views in one image; no scenery; no thin wires; no floating accessories; no transparent body; no cropped form; no typography.

**Original videos:**

1. 60–90 seconds, “Reference + prompt in ChatGPT Images.”
2. 60–90 seconds, “The same method in Adobe Firefly.”

**External references:**

- [Images in ChatGPT](https://help.openai.com/en/articles/11084440-images-in-chatgpt)
- [Adobe Firefly: generate images from text descriptions](https://helpx.adobe.com/firefly/web/work-with-images/generate-images/generate-images-from-text-descriptions.html)
- [Adobe Firefly: match composition to a reference](https://helpx.adobe.com/firefly/web/work-with-images/generate-images/match-image-composition-to-reference-image.html)

**Documentation:** Copyable prompt template, prompt/version log, and image selection rubric.

### Module 3 — Build the First Volume

**Header:** ASK A FLAT IMAGE TO BECOME A FORM  
**Subhead:** Conversion is a proposal. Orbit before you trust it.  
**Objective:** Convert the selected image to a 3D mesh and evaluate the result from every side.

**Input:** Selected PNG/JPG  
**Tool choices:** Meshy or Tripo; free tier first, instructor credits as backup  
**Timebox:** 45 minutes  
**Output:** Original model export, ideally STL for print and GLB/OBJ as a source copy when available  
**Pass check:** Recognizable front, plausible back, connected body, no missing main mass

**Different examples for this module:** Organic creature vs hard-surface household object.

**Teach:**

- Upload and generate.
- Separate shape quality from texture quality.
- Orbit top, bottom, back, and underside.
- Save the unmodified original before repairing.
- Use one second generation only when the first result fails a structural requirement; preserve backup credits.

**Original videos:**

1. 60–90 seconds, “Image-to-3D in Meshy.”
2. 60–90 seconds, “The equivalent workflow in Tripo.”

**External references:**

- [Meshy generation-method guide](https://docs.meshy.ai/en/webapp/guides/choosing/generation-method)
- [Meshy export formats](https://docs.meshy.ai/en/webapp/guides/platform/export-formats)
- [Tripo official tutorial center](https://www.tripo3d.ai/tutorials)

**Documentation:** Mesh-generation log: tool, generation ID, settings, credit source, exports.

### Module 4 — Read the Mesh

**Header:** INSPECT BEFORE YOU REPAIR  
**Subhead:** A mesh can look complete and still fail as an object.  
**Objective:** Triage the conversion without turning the workshop into a full modeling course.

**Input:** Original 3D conversion  
**Tools:** Tool viewer, Bambu Studio preview, optional Blender inspection  
**Timebox:** 25 minutes  
**Output:** Green/yellow/red triage decision  
**Pass check:** Participant can name the failure and choose continue, repair, or regenerate

**Different example for this module:** A visually convincing watertight mesh vs a broken underside/non-manifold mesh.

**Five-point inspection:**

1. **Silhouette:** Does the object read from multiple angles?
2. **Continuity:** Are main masses connected?
3. **Base:** Can the object contact a plate or supports safely?
4. **Thickness:** Will narrow details survive at the chosen scale?
5. **Surface:** Are holes, spikes, shells, or internal fragments likely?

**Triage:**

- **Green / Slice:** structurally coherent; proceed.
- **Amber / Clinic:** one or two repairable issues; open Repair Clinic.
- **Coral / Regenerate:** missing body, unusable rear geometry, extreme fragmentation, or repair would become redesign.

**Original video:** 75–90 seconds, “Five mesh checks in one orbit.”  
**External reference:** Meshy post-processing decision guide or Blender 3D Print Toolbox manual.  
**Documentation:** Printable mesh-inspection card.

### Module 5 — Repair Only What Matters

**Header:** OPTIONAL MESH REPAIR CLINIC  
**Subhead:** Fix the obstacle. Preserve the participant’s concept.  
**Objective:** Repair bounded, production-relevant mesh problems without making Blender a required path.

**Input:** Amber-triage mesh  
**Tools:** Blender 3D Print Toolbox and basic mesh cleanup  
**Timebox:** Up to 40 minutes in parallel  
**Output:** Versioned repaired STL  
**Pass check:** Repair is watertight enough to slice, keeps the concept, and does not introduce fragile geometry

**Different example for this module:** One mesh with a hole/loose geometry and a clean repaired copy.

**Clinic menu:**

- Recalculate normals.
- Delete loose geometry.
- Fill bounded holes.
- Make manifold when appropriate.
- Apply scale.
- Join a separated main mass when it is an obvious repair.
- Add or flatten a base only when needed for production.

**Stop rule:** If a repair would require sculpting a missing half, rebuilding anatomy, or changing the concept, return to image/conversion rather than consuming the class in Blender.

**Original video:** 90 seconds, “Minimum viable mesh repair in Blender.”  
**External references:**

- [Blender 3D Print Toolbox](https://docs.blender.org/manual/en/latest/addons/mesh/3d_print_toolbox.html)
- [Blender mesh cleanup](https://docs.blender.org/manual/en/latest/modeling/meshes/editing/mesh/cleanup.html)

**Documentation:** Clinic decision tree and repaired-file naming convention.

### Module 6 — Place It in Gravity

**Header:** SIZE, ORIENT, SUPPORT  
**Subhead:** The object meets gravity before it meets the printer.  
**Objective:** Choose production tier, establish real scale, orient the model, and assign a support rating.

**Input:** Green or repaired mesh  
**Tools:** Bambu Studio  
**Timebox:** 50 minutes  
**Output:** Positioned model with tier, dimensions, orientation, and support plan  
**Pass check:** Stable plate relationship, realistic fine-detail thickness, acceptable support removal

**Different examples for this module:** A low-support bust and a dynamic high-support full-body figure.

**Order of operations:**

1. Select exact printer profile: [MODEL PENDING].
2. Select plate/nozzle profile: [PENDING].
3. Import mesh.
4. Confirm unit scale.
5. Choose Miniature or Sculpture tier.
6. Orient for stability and visible-surface quality.
7. Add automatic supports; modify only where needed.
8. Record Low/Moderate/High support rating.

**Teach the tradeoff:** An orientation can reduce support but damage the visible surface, or improve visible detail while adding time and scarring.

**Original videos:**

1. 60–75 seconds, “Scale and orient before supports.”
2. 60–90 seconds, “Automatic supports and what they cost.”

**External references:**

- [Bambu Studio Support guide](https://wiki.bambulab.com/en/software/bambu-studio/support)

## 7. Print Attempt & Recovery Policy

### Participant-facing language

> Your workshop includes one approved print attempt. If that attempt fails because of a qualifying production problem or a repairable mesh problem, one automatic reprint attempt is included. Redesigns, larger sizes, new colors, extra copies, or changes requested after approval are separate from the included recovery attempt.

### Included automatic reprint

The first attempt qualifies when the failure is attributable to:

- First-layer or bed-adhesion failure under the approved setup.
- Filament feed, runout, tangle, jam, or nozzle/extrusion failure.
- Machine, power, network, or file-transfer interruption after approval.
- Support collapse or print detachment under the approved orientation/settings.
- A bounded mesh defect revealed during slicing/printing that can be repaired without redesigning the concept.
- Another documented production failure jointly identified by the instructor and Moonlighter operator.

### Repairable mesh means

- The original concept and overall form remain unchanged.
- The adjustment is limited to closing a hole, fixing normals, removing loose/internal fragments, connecting an obvious main mass, thickening a narrowly bounded fragile feature, or stabilizing the base.
- The repair can be completed with reasonable production effort.

### Not included

- Participant-requested redesign, pose, color, scale increase, or material change.
- Additional copies or a second creative iteration.
- A model changed after approval without instructor/Moonlighter review.
- A concept whose missing or invented geometry requires substantial remodeling.
- Damage after successful production or pickup.
- Failure caused by participant handling outside supervised procedures.

### Recovery workflow

1. Operator marks the attempt **Failed / Review**.
2. Photograph the failure and record time, printer, file, settings, and failure type.
3. Instructor or Moonlighter identifies production-only retry vs bounded mesh repair.
4. If mesh repair is required, create a new version; never overwrite the approved source.
5. Queue one automatic reprint.
6. Record the change and outcome.
7. Keep the one-week promise when operationally possible; notify the participant if recovery changes the date.

## 11. Visual system

### Direction

**Hybrid editorial + technical.** The interface should feel like a contemporary artist workbook that becomes more instrument-like when a decision affects the machine. It should not imitate a dense slicer dashboard across every screen.

### Color tokens

| Token | Provisional value | Use |
| --- | --- | --- |
| Paper | `#F4F1E8` | Primary background; warm editorial field |
| Ink | `#171916` | Text, borders, high-contrast controls |
| Soft gray | `#D8D7D0` | Rules, inactive states, technical grids |
| Digital / cyan | `#277DA8` | Reference, prompting, generation, conversion |
| Controlled / amber | `#D88A24` | Account limits, timing, supports, queue warnings |
| Diagnose / coral | `#CC5A55` | Failed checks, repair, print recovery |
| Verified / green | `#347A52` | Approved, ready, complete |
| Moonlighter accent | `[HEX PENDING]` | Brand moments and the third filament; must pass contrast checks |
| Black filament | Physical swatch pending | Material choice |
| White filament | Physical swatch pending | Material choice; card requires visible border |

No meaning may depend on color alone. Every state pairs color with an icon, phase name, and written status.

### Typography

- **Display/editorial:** [MOONLIGHTER BRAND TYPEFACE PENDING] or a high-legibility contemporary grotesk/serif pairing.
- **Interface/body:** neutral sans-serif with clear numerals.
- **Technical metadata:** mono or tabular-numeral style used sparingly.
- Sentence case for instructions; uppercase reserved for phase eyebrows and small production labels.

### Spacing and breathing room

- Base spacing unit: 8 px equivalent.
- 24–32 px inside compact cards.
- 64–96 px between content groups.
- 120–180 px between major editorial modules on large screens.
- Never place more than one dominant image, one main task, and one checkpoint in the initial viewport.
- Troubleshooting and external links remain collapsed until requested.

### Image-to-UI balance

- Creative stages: approximately 65% image / 35% UI.
- Validation and repair: approximately 50% comparison / 50% technical guidance.
- Slicing and queue: approximately 35% image / 65% technical UI.
- Archive/continuation: return to approximately 60% artifact/process image / 40% checklist.

### Icon family

Use one consistent outline icon family. Required semantic icons:

- `Image` — reference
- `Camera` — photograph
- `Upload` — supplied file
- `Sparkles/Wand` — AI image transformation
- `Box/Orbit` — 3D conversion
- `Scan/Search` — mesh inspection
- `Wrench/Bandage` — repair clinic
- `Ruler` — real scale
- `Rotate 3D` — orientation
- `Scaffold/Triangle` — supports
- `Layers` — slicing
- `Clock` — estimate
- `Printer` — machine assignment
- `Shield Check` — approval
- `Refresh/Recovery` — qualifying reprint
- `Archive/Folder` — project package
- `Bell` — pickup notification

Vendor logos are not substitutes for semantic icons. Logos appear only inside tool-choice and documentation cards after Moonlighter supplies/approves assets or the official vendor asset is verified.

## 12. Interaction and immersive flourishes

Interactions should clarify transformation, material, or status. They should never delay the task.

### Recommended

- **Pipeline morph:** hero transitions on scroll from flat reference to shaded mesh to sliced layers to physical print. Provide static panels under reduced motion.
- **Orbit reveal:** draggable 3D model at conversion and validation stages; presenter uses a slow turntable autoplay with pause.
- **Reference spotlight:** hover/focus isolates strong silhouette and flags shadow, crop, or clutter annotations.
- **Prompt chips:** selecting a quality inserts plain-language structure into the editable prompt.
- **Before/after scrub:** image-to-3D, broken/repaired, and unsupported/supported comparisons.
- **Layer peel:** slicing section lets the user drag through representative layers; a static annotated screenshot is the fallback.
- **Filament tactility:** hover/focus slightly enlarges a macro filament/print texture and reveals printer availability.
- **Time elasticity:** resizing a demonstration model visually stretches the estimated-time bar, teaching that volume does not scale linearly with height.
- **Approval pulse:** one restrained outline animation when a file becomes Ready; never continuous.
- **Queue timeline:** approved jobs settle into printer columns and pickup sequence.

### Hover/focus rules

- Hover and keyboard focus produce the same information.
- Movement: 2–4 px, 150–220 ms, no dramatic spring effects.
- Cards gain border contrast and reveal secondary metadata; they do not jump or rearrange.
- Tooltips are never the only place required information appears.
- Touch devices use tap-to-expand.
- Respect `prefers-reduced-motion`; all core content remains available without animation or JavaScript.
